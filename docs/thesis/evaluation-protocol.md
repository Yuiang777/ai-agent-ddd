# 引用核验实验执行与标注协议

## 一、实验前置条件

1. 确定具体法域、业务问题、法源许可、官方出处和统一的法源版本快照；不接入未经授权的案卷。
2. 为每道题记录：问题 ID、问题原文、法域、问题类型、事实时间、适用法律时点、可引用文档 ID/版本/条款、证据原文、是否可回答、应拒答原因。
3. 法律专业人员独立标注每条生成结论与引用原文之间的支持关系，状态至少包括“支持 / 不支持 / 无法判断”；保存分歧和仲裁记录。
4. 固定模型版本、模型参数、语料快照、检索设置和随机种子（若模型提供）；三个实验组使用相同的问题集合。

在运行任何实验组前，登记题目的来源、拟覆盖的题型、纳入/排除条件和抽取顺序，冻结题目 ID 清单及其版本；不能看到某组回答后再移除不利题目或重写问题。若因原始材料遗失而不得不排除，按第三节规则同时处理该题三组全部轮次，保存原清单、排除理由及排除前后题型计数。该步骤是待执行的实验控制，不代表目前已有真实题库。

在观察答复之前，为每个 `(questionId, run)` 用预先记录的随机种子确定三组执行顺序，并保存完整运行序列。三组使用同一冻结题目、法律适用时点和模型参数；每轮重置会话上下文，关闭跨组缓存或记录无法关闭的缓存影响，记录实际请求时间、模型响应标识及失败重试次数。若模型服务或语料版本在实验中变动，暂停采集并记录变动范围，不将不同版本的轮次直接拼接成同一次对照实验。顺序随机化、日志与人工复核是待执行步骤；当前脚本不自动核验这些运行条件。

冻结题库后，可在仓库外建立 UTF-8 JSONL 清单（每行至少含唯一 `questionId` 和合法的 `lawAsOf` 日期），执行 `node scripts/plan-evaluation-runs.mjs 路径/题目清单.jsonl 轮次数 随机种子`。工具只按题目清单顺序列出每题各轮的三组执行顺序，使用种子、题目 ID、轮次与组名的 SHA-256 排序键，并附清单文件散列；题目解析与散列计算使用同一次读取的原始字节，避免文件在两次读取之间变化而使计划内容与散列错配；把种子、散列、输出计划和代码提交号一同冻结。输出到标准输出，不执行模型请求，也不生成问题、法源、答案、主张或评分；它不是计算器的标注输入。更换清单字节或种子须重新登记计划，实验人员仍须自行核对模型参数、版本和每轮实际执行日志。

## 二、实验分组与错误分类

| 分组 | 规则 | 目的 |
| --- | --- | --- |
| 直接生成 | 不提供检索材料 | 观察基线生成和无依据内容 |
| 普通 RAG | 提供相同的候选材料但不执行逐条核验 | 比较检索对引用的影响 |
| 核验方案 | 使用本仓库的主张—证据编号—摘录核验与人工复核门控 | 验证错引阻断能力及代价 |

至少单独统计以下错误类型：不存在的条文；正确条文但摘录篡改；引用其他文档；真实摘录但推论不成立；已修订或不适用于问题时间点；证据不足仍给肯定答案；多条主张中仅部分有依据。系统当前**只自动阻断部分来源/摘录类错误**；其他类别必须依赖人工标注分析，不得宣称已自动解决。

## 三、记录字段与统计

每次运行保留问题 ID、实验组、运行序号、模型及提示词版本、文档快照 ID、候选证据编号、生成主张、来源核验状态、人工支持判断、最终展示文本、复核标志、耗时与 token 使用量（若可用）。将公开材料和私有案件材料分开保存，私有材料仅记录匿名化标识。

统计时分别计算：来源可定位率、摘录准确率、人工支持率、无支持结论展示率和拒答率；对于“来源成功但语义错误”，应计入摘录准确但人工支持失败。报告每组样本数、置信区间或重复运行波动范围，明确未完成的标注和跳过项。不要将单元测试通过率当作论文实验准确率。

若报告抽样不确定性，应以**问题 ID**而不是单条主张作为重抽样单位：一次抽中某题，就同时保留其三组、全部轮次及其主张，按每次抽样的分子与分母重新计算各组比率及配对差值；预先记录随机种子、抽样次数、区间算法和无法计算分母的重抽样次数。不得把同一问题的重复回答或一份回答中的多条主张当成相互独立的样本。当前 `legal-citation-evaluation.mjs` 只给出计数和点估计，**不计算置信区间或显著性**；真实标注和重抽样未完成前不能填入区间或改善幅度。

### 标注文件与计算工具

使用 JSONL 文件，每行代表同一问题在一个实验组的一次运行。下列三行只是**结构示意，不是实验数据**；真实标注应逐项替换，并附记录对应的材料版本和判定依据：

~~~jsonl
{"questionId":"示例-001","run":1,"group":"direct","modelVersion":"示意模型版本","promptVersion":"示意提示词版本","corpusSnapshotId":"示意语料快照","lawAsOf":"2026-01-01","answerable":true,"refused":true,"claims":[]}
{"questionId":"示例-001","run":1,"group":"rag","modelVersion":"示意模型版本","promptVersion":"示意提示词版本","corpusSnapshotId":"示意语料快照","lawAsOf":"2026-01-01","answerable":true,"refused":true,"claims":[]}
{"questionId":"示例-001","run":1,"group":"verified","modelVersion":"示意模型版本","promptVersion":"示意提示词版本","corpusSnapshotId":"示意语料快照","lawAsOf":"2026-01-01","answerable":true,"refused":true,"claims":[]}
~~~

四个溯源字段 `modelVersion`、`promptVersion`、`corpusSnapshotId`、`lawAsOf` 必须填写真实运行配置和题目适用法律时点（ISO 日期）；脚本拒绝缺失字段、非法日期、模型或语料快照不一致、同一组提示词版本变化、同一题时点变化。示意值不可用于论文结果。

读取标注文件时使用严格 UTF-8 解码；遇到非法字节或截断的多字节字符立即报错，命令行不输出指标，避免替换字符悄悄改变问题 ID 或溯源信息。文件首只允许一个可选 BOM，中间行或重复的 BOM 不作为额外文件头忽略。这是文件完整性防护，不验证标注事实是否正确。

标注文件保存为 UTF-8 JSONL；计算脚本兼容文件首字节的 UTF-8 BOM，但不忽略中间行的意外 BOM。保存为本地标注文件后执行 `node scripts/legal-citation-evaluation.mjs 路径/标注记录.jsonl`。三个实验组分别为 `direct`、`rag`、`verified`；同一个 `questionId` 与 `run` 必须在三组均出现，每道题须采用相同次数、从 1 开始连续的重复轮次；重复、遗漏或不平衡会报错。`answerable` 表示人工判定该问题可在指定材料和时点下回答；`refused` 表示运行对该问题没有展示任何候选主张；如果有供律师阅读的候选主张，记录 `refused:false`，即便结果仍要求人工签发。同一道题在三个实验组及所有轮次中必须使用相同的 `answerable` 金标准；`refused` 必须与 `claims` 中是否存在 `displayed:true` 严格互补，否则输入无效。问题 ID 必须非空，且不得有首尾空白或换行。**这只检验录入字段的一致性，不证明原始答复已完整拆分。**

每条 `claims` 包含 `evidenceLocated`、`quoteMatched`、`humanSupport`、`displayed`。`humanSupport` 必须是 `SUPPORTED`、`UNSUPPORTED` 或 `UNCERTAIN`，由独立人工标注，不得复制系统的 `SOURCE_MATCHED` 值代替。`displayed` 表示该主张在结果页面或报告中实际可见；拒答记录不得同时有 `displayed:true`。原文匹配前必须能定位来源。`UNCERTAIN` 不纳入人工支持率分母；如存在尚未裁决、却已对外展示的主张，无依据结论率输出 N/A 并同时报告待判条数，避免低估风险。

每组汇总结果同时保留模型版本、该组提示词版本、语料快照 ID、题目数及每题运行轮次，便于与原始标注文件核对；`metricCounts` 给出各项指标可复核的分子与分母计数，各题适用法律日期仍以逐条记录为准。计算器返回 0 至 1 的小数（展示时乘 100%），在分母为零时输出 `null`（对应 N/A），并分别报告不可回答问题的正确拒答率及可回答问题的误拒率。未经完整复核的数据不应直接填入论文最终结果表。

### 人工判定口径

- `evidenceLocated=true`：标注员能够独立打开与题目适用时点一致的文档版本，并定位到该条主张所引片段；仅有模型生成的文档名、路径或条号不算定位成功。
- `quoteMatched=true`：在已定位的同版本原文中找到候选摘录；仅允许记录核验规则明确的 Unicode 空白差异，不能把意思相近的改写当作原文摘录。
- `humanSupport=SUPPORTED`：独立判断该版本原文确实支持这条结论及其限制条件；真实摘录不足以推出结论时标记 `UNSUPPORTED`，证据无法裁决时标记 `UNCERTAIN` 并保留理由。
- `SUPPORTED` 的前提是该条主张引用的同版本来源已被独立定位；若 `evidenceLocated=false`，标注器拒绝将其计为人工支持。原文摘录未匹配时，仍可单独判断已定位版本是否支持结论，但必须如实记录 `quoteMatched=false`，不得将两个指标混为一谈。
- `displayed=true`：以实际用户可见的报告和页面为准，不能因内部日志产生候选就判定已展示；保留截图或脱敏导出及运行 ID 便于抽样复核。
### 人工标注执行顺序

1. 在预先冻结的题库中为每道题登记问题原文、适用时点、权威来源版本、应回答/应拒答金标准；不同实验组不能另行改动此金标准。
2. 对每组、每轮输出保留原始完整答复及候选主张；人工逐条拆分所有实际展示的实质性法律结论（直接生成和普通 RAG 的自由文本也一样），连同未展示的已生成主张录入 JSONL 的 `claims`，按页面/报告标记 `displayed`。无引文或无法定位的来源应标记 `evidenceLocated:false`，不能因没有引用就不录入结论。只有原始答复确实没有展示任何实质性结论时，空主张数组才可标记 `refused:true`；无法可靠拆分或无法确认展示内容时，不得将该轮伪装成拒答。应登记缺失原因；若无法补齐，因脚本要求所有题目轮次相同，须从三组同时排除该问题的全部轮次，单独报告排除题目数和受影响轮次。
3. 两名具备相应法域知识的标注人员独立对照权威来源判断定位、原文摘录和结论支持关系；分别记录版本/时点和判定理由。分歧由第三人仲裁；未仲裁时填写 `UNCERTAIN`，不得默认“支持”。
4. 对照原始运行日志逐条复核 JSONL 后运行计算器；保存题库、版本快照、标注记录、仲裁记录、代码版本和执行命令，且与论文结果表一一对应。当前示例三行只检查格式，不是实验样本。

### 从原始输出到汇总结果的审计索引

正式采集时另建不公开的审计索引，而不是把待公开的 JSONL 当作完整证据。每次运行用 `(questionId, run, group)` 关联题库条目、原始请求/响应、当时实际展示的页面或报告、模型与提示词配置及证据版本快照；对拆出的每条主张再记录原始输出中的位置、引用的文档 ID/版本/条款、两位标注者各自的判断与理由、仲裁结论。保留文件的 SHA-256 和计算时的代码提交号，避免同名文件被替换后无法追溯。原始材料和截图可能含隐私，须先取得使用授权，按权限隔离存储，发布时只提供获准公开的脱敏材料与索引。

汇总前逐条核查：JSONL 中的主张数、顺序、`displayed` 和 `refused` 与原始输出及可见报告一致；两份独立标注在仲裁前不能互相覆盖；分歧未决时 `humanSupport` 仍为 `UNCERTAIN`。原始输出、实验前冻结的来源快照遗失或展示状态无从复核属于采集材料缺失，应登记原因，按前述配对与轮次规则处理，不得凭印象补填。相反，原始输出与冻结材料均完整时，模型未附来源、伪造条文或引用无法定位的版本，属于需要保留的评测失败，不能借“来源版本无法定位”之名排除；此时填写 `evidenceLocated=false`、`quoteMatched=false`，人工支持状态按判定口径填写，未能裁决时仍为 `UNCERTAIN`。现有计算脚本只验证 JSONL 的字段与配对一致性，不读取审计索引或文件散列，以上核查须由实验执行者另行完成。

### 独立标注空白表

`docs/thesis/annotation-worksheet.csv` 只有表头，没有题目、法源或实验结果。实验协调员应在仓库外复制两份，分别交给标注者独立填写；每行一条主张，用协调员分配的 `caseToken` 和从 1 开始的 `claimOrdinal` 标识。协调员将令牌与 `(questionId, run, group)` 的对应关系单独保存在受限台账，标注时尽可能不透露实验分组；无主张的拒答轮次只在运行台账登记，不能凭空在主张表中添一行。`reviewerId` 用匿名代号，`sourceDocumentId`、`sourceVersion`、`sourceLocator` 只填实际核对过的来源信息；无可定位来源时留空并填 `evidenceLocated=false`。`rawOutputSha256` 来自保存的原始输出文件，不是模型声称的散列。

`evidenceLocated`、`quoteMatched`、`displayed` 仅填写 `true`/`false`；`humanSupport` 仅填写 `SUPPORTED`、`UNSUPPORTED` 或 `UNCERTAIN`，`reason` 填写判定依据及待解决分歧。两份标注先按令牌、序号对齐，记录分歧和第三人仲裁，再由协调员结合运行台账整理为计算器所需的 JSONL；本 CSV **不是**计算脚本的输入。含原始答复、法源及标注者信息的填写版不得直接提交仓库；正式公开前须按授权脱敏。
