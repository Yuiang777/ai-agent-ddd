# 基于大模型的引用可验证法律问答系统的设计与实现（论文初稿）

> 本文是与当前实现对应的初稿，不是可直接提交的定稿。学校格式、真实语料授权、参考文献和实验数值待补齐；不得将示例测试写成真实法律效果评测。

## 摘要

大模型法律问答可能出现虚构法条、错引原文或真实引文无法支持结论的问题。本文在现有混合检索和法律工作流上实现逐条主张来源核验：为本轮证据编号，要求模型输出法律主张、证据编号和原文摘录，确定性检查编号、引文原文、来源定位及版本元数据；任一主张失败即不展示候选结论，全部来源匹配时也仅展示需律师复核的候选主张。系统不将原文匹配等同于法律结论正确。本文提供程序测试及真实问题对照评测方案，量化实验尚待执行。

**关键词：**法律问答；检索增强生成；引用可追溯；大语言模型；人工复核

## Abstract

Large language models can produce plausible legal answers with fabricated provisions, inaccurate quotations, or quotations that do not support the stated conclusion. This thesis describes a prototype legal question-answering system that adds claim-level citation checks to an existing retrieval and workflow pipeline. For each retrieved passage, the system assigns an identifier scoped to the current run. The model is asked to return a claim, its evidence identifier, and a quoted excerpt. A deterministic verifier checks identifier membership, source location, available version metadata, and whether the excerpt occurs in the retrieved text after a limited whitespace normalization. If any claim fails these checks, the prototype withholds the candidate claims; a successful source match still requires legal review before use. The check does not establish that a legal inference is sound, that a source is authoritative, or that the cited law applies at the relevant time. Program tests cover malformed citations and failure paths, while a separate protocol specifies how a future evaluation should compare direct generation, conventional retrieval-augmented generation, and the prototype using the same questions and human annotations. That real-world comparative evaluation has not yet been conducted.

**Keywords:** legal question answering; retrieval-augmented generation; citation traceability; large language models; human review

## 第一章 绪论

法律问答需要回答与所引材料建立可审计关系。“引用可验证”至少包括来源存在、摘录准确、语义支持与适用时点正确四层。本次实现自动检查前两层的相关元数据和原文匹配；第三、四层需由法律专业人员核查。研究目标是降低错引被展示为已核验结论的风险，不承诺所有法域和案件类型的自动法律判断。

### 1.1 研究问题与范围

本文针对两类可以分开检验的问题开展设计。其一，在模型给出多条法律主张时，系统能否逐条定位到**本轮检索**的材料，并阻止不存在的证据编号、篡改的摘录和缺失的来源信息进入最终报告？其二，来源和原文均匹配时，界面及工作流能否仍将结论保留在人工复核环节，而不是把程序检查写成法律判断？前一问题可以通过构造缺失、错引与混合主张的程序测试检查门禁行为；后一问题需要检查报告状态和实际展示内容。要评价这些门禁是否改善真实问答质量，仍须按第五章方案对同一批问题开展人工标注的三组对照实验，本文目前不据程序测试推断改善幅度。

本文交付的是一种“先核对引用再形成候选结论”的可运行原型，而非法律意见自动签发工具。材料的权威性、修订前后适用关系、事实是否完整以及引文是否真正支持推论，都不能由字符串包含关系确认。论文将机器可检查的来源条件与必须由专业人员判断的法律条件分别叙述，并以实际可重放的测试记录对应实现，不用未接入的公共检索或持久化审计功能充当成果。

## 第二章 需求分析

功能需求：来源检索、主张结构化、逐条来源绑定、错误原因输出、证据不足时拒绝自动签发、人工复核。非功能需求：可追溯版本与来源、有限输入长度、来源隔离、可复现的测试和透明的能力边界。系统中的模型路由标识不等于用户身份，正式环境还须验证多租户权限与隐私保护。

## 第三章 系统设计

### 3.1 系统结构

系统采用多模块 Java 后端和前端；现有法律知识导入提供文档及片段元数据，混合检索获得候选证据，工作流依次运行受理、检索、推理、引用、后续风险分析、复核和报告等节点。新增核验器位于引用节点，内部持有本轮检索片段，公共返回对象不附带原始证据列表。非诉讼问答的报告只在全部来源检查通过时展示标记为“待人工复核”的候选主张；诉讼路径保持内部底稿和律师签发门禁。

### 3.2 数据模型和算法

每条主张表示为 C=(text,evidenceId,quote)，其中证据编号限定为本轮 E1、E2 等，quote 为对应片段中的连续摘录。核验器先限制条数与长度，再检查证据编号、文档和片段定位、版本及已有来源校验和；若记录的生效日期晚于当前系统日期则失败，最后去除 Unicode 空白字符（含全角空格及不换行空格）并检测摘录是否在证据原文内；不进行同义词或标点改写。结果包括逐条状态、总体是否来源匹配和失败原因。任一失败不展示候选主张，全部成功也标记人工复核。“SOURCE_MATCHED”仅表示本轮来源原文匹配，不能表示语义支持、时效正确或来源可信。已有校验和为元数据，尚未重新读取原件验算。

### 3.3 信任边界与状态门禁

用户问题、上传材料、检索片段和大模型输出都作为待核验数据处理，而不是可改变规则的指令。推理节点只能引用本轮检索到的证据编号；检索质量门禁未通过时不形成自动法律结论。引用节点检查主张结构与摘录定位，并在对方分析、策略分析和风险分析之前执行。来源核验失败时，后续实体分析不继续，报告转为人工复核待办；诉讼案件仍需律师独立签发。

| 阶段 | 输入或门禁 | 对外行为 |
| --- | --- | --- |
| 检索 | 本轮法源片段及来源元数据 | 返回状态和复核原因，不返回内部原始证据列表 |
| 推理 | 检索质量允许 | 产生内部主张、证据编号和摘录；引用节点之前不对外流式展示实体分析 |
| 引用 | 编号、原文、定位、版本元数据等逐条核对 | 全部通过才形成来源匹配的候选引用；任一失败不输出部分候选引用 |
| 复核与报告 | 来源匹配仍不等于语义支持 | 始终提示人工判断；诉讼报告只能作为未签发的内部底稿 |

前端仅在工作流完成事件提供有效终态及非空最终正文后展示报告；节点级流式输出不直接作为报告展示。受理暂停或执行失败时不展示候选风险、引用和诉讼分析；即使先收到完成事件，只要后续流式解析失败，也撤回本次候选结果。失败事件中断流式读取，避免其后的完成事件重新恢复候选结果；错误消息按字符串类型检查后展示，避免异常对象引起页面渲染失败。连接中断、结束事件缺失或执行失败时不允许登记报告。

这里的质量门禁只阻断已识别的风险，不构成对法律结论正确性的数学证明；特别是来源路径与校验和仅检查元数据存在，没有在每次问答中重新拉取原件校验真实性。

### 3.4 逐条检查与整体阻断

核验输入是主张序列与**该次运行**得到的证据序列；编号 E1、E2 等仅按这份序列的位置解释，不跨轮次复用。程序拒绝空列表和超过 20 条的列表；单条主张正文最长 1200 个字符、摘录最长 360 个字符，去除 Unicode 空白后的摘录至少 8 个字符。每条主张依次检查字段非空、编号能否命中、本轮材料是否带有文档及来源路径、版本与已有校验和元数据是否存在、可解析的生效日期是否晚于运行时钟，最后检查规范化摘录是否为证据片段的连续子串。字段不合格或任一检查失败都会得到具体状态，而不是默认为“来源匹配”。

令 `s_i` 表示第 `i` 条主张的核验状态。只有主张数在允许范围内且**所有**状态均为 `SOURCE_MATCHED`，整体来源检查才为真；任一失败都不拼接部分成功主张，也不把部分引用加入候选列表。来源定位检查依据的是本轮检索对象携带的字段，校验和仅检查元数据是否存在，未重新读取对象或计算文件摘要；未记录生效日期的资料不会因这一字段自动失败，已废止或需历史时点判断的资料也不能由该规则充分识别。上述逻辑对应 `LegalClaimCitationVerifier` 与工作流的 `CitationAgent`；它们输出“来源匹配”或具体错误原因，不输出“法律论证成立”。

## 第四章 实现说明

LegalOrchestratorService 在检索节点保存本轮候选证据，推理节点要求 JSON 中提供 analysis 与 claims 数组；引用节点使用 LegalClaimCitationVerifier 核验，复核节点无论原文是否匹配都提示需要人工确认语义和法律适用，报告节点仅将全部通过来源核验的主张列为候选并附定位与版本。未通过核验的候选结论不会进入报告或顶层引用列表。流式事件中，引用前节点的自动分析文本不对外推送；最终流式结果保留报告正文、候选引用、风险条目和复核状态；诉讼案件的结构化摘要仅保留基本信息与签发状态，不包含未逐条核验的自动分析。同步结果在来源核验失败时同样移除这些自动分析字段，诉讼内部底稿用门禁提示取代未核验内容。即使来源匹配成功，结构化段落也只是候选底稿，未逐条证实语义支持。模型输出结构损坏或检索证据缺失时转人工复核。候选引用中的主张、摘录和来源字段在排版前折叠换行并规范括号，避免恶意文本伪造另一条 Markdown 引用。诉讼底稿的当事人名称和程序字段也做单行化，避免输入换行伪造“律师已签发”等报告标题。

### 4.1 模块职责与对外投影

领域层工作流引擎负责节点拓扑、状态合并与事件分发；应用层负责检索、证据编号、主张结构化、引用核验和报告门禁。`LegalClaimCitationVerifier` 对输入执行确定性检查，不调用大模型判断“法律上是否支持”。模型只产生候选主张和摘录，核验器决定来源是否可追踪，律师决定结论是否可采纳。

系统在流式接口中仅向用户推送报告节点的正文，隐藏前置节点的临时推理文本；前置节点完成事件也不携带自动分析字段。最终流式事件保留案件基本元数据但不携带未经逐条核验的结构化分析；同步接口移除原始 OCR/案卷片段、内部检索证据、未经核验主张和核验对象。出现服务异常时，运行、上传授权及上传流式接口只返回通用失败提示；流式失败事件的消息及额外数据字段也经公开投影脱敏，避免原始模型输出或文件路径经异常信息外泄。此处是“对外投影”保护，内部节点仍可为后续核验使用必要材料。

### 4.2 核验边界和失败回退

页面依据工作流的人工复核状态显示警告，不以原因列表是否非空判断是否需要复核。原因未返回时只提示系统要求人工复核，不补写具体原因，也不显示无需强制复核的成功提示。

报告页面对 Markdown 图片使用纯文字占位，不自动加载模型生成的图片地址，避免展示报告时向第三方图片站点发出请求。此限制仅作用于页面渲染，不代表已核验普通链接的可信性，也不改变保存的报告原文；导出和其他消费端仍需独立处理外部资源。
报告中的链接仅允许 HTTP(S) 协议，外部链接使用新窗口和 `noreferrer noopener` 属性；其他协议只显示文本，不直接执行或跳转。

核验输入为本轮生成的主张集合和本轮检索证据集合，主张超过 20 条或缺少主张时直接失败。逐条检验非空字段、主张与摘录长度、证据编号在本轮是否存在、定位和版本元数据是否齐备、已有生效日期是否晚于系统日期，以及去空白后的摘录能否在片段文本中找到。任何一条不匹配都会令本轮来源核验整体失败，不输出其他条目的部分候选引用；后续风险与诉讼策略节点不继续产生未核验的实体分析，报告转人工复核。检索片段自身可能错误或过时，摘录匹配也无法证明法源权威性及推论成立，因此此流程是一道可审计的来源门禁，不是自动法律意见签发机制。

### 4.3 前端业务工作台设计

检索状态使用中文标签区分正常、降级、证据不足和不可用；缺失、无法识别或类型异常的状态统一显示“状态未知”。已生成候选报告但未收到检索状态时，不继续显示“未执行”。该标签仅描述检索服务状态，不表示引用或法律结论已经核验。

报告排版对长网址和连续字符启用自动换行，宽表格与代码块在各自区域内滚动，不以截断或改写正文消除页面溢出。表格滚动区提供可聚焦的具名区域；模拟浏览器回归检查不同视口下无整页横向溢出，并核对长文本和代码行仍与输入一致。

窄屏按报告、流程节点、执行记录的顺序组织内容；桌面保留并列展示。流程节点列表限制可视高度，并提供带名称的可聚焦滚动区域，保留全部节点而不让长列表无限拉高报告卡片。

案件分析页采用中文节点状态与事件名称，并以普通执行图标代替生成式装饰图标；原始事件码保留在悬停提示中。流程结束后，若某节点只有开始事件而没有完成或失败记录，页面标记为“状态未确认”，不继续显示执行中，也不推断为成功。

前端不将系统包装为可以直接替代律师的“智能助手”，而是按法律事务办理流程组织页面。侧边导航分为业务工作台、知识与资产、协作与治理三组；工作台展示事项阶段、待补材料、待人工复核和待律师签发等业务状态，咨询页面明确区分“咨询草稿”“来源未核验”和“正式交付需律师审核”。

合同审查、风险巡检、法律事项和法规资料使用独立入口，避免把不同数据权限和办理阶段混合在对话窗口中。风险巡检目前尚无后端任务接口，页面仅呈现未接入状态，不提供模拟运行或虚构风险数值。引用核验结果以来源状态、版本信息和复核提示呈现；来源匹配成功只代表摘录可以在当前证据片段中定位，不直接显示为“法律意见已成立”。页面中的模型生成内容统一标记为办案辅助，正式交付仍以事项记录、核验结果和律师审核为准。文本咨询对每条模型回复标注来源未核验，并移除易暗示律师背书的法槌头像与未持久化的临时会话编号。

该设计服务于可解释性和答辩演示：评审者可以从事项进入材料，再进入工作流和引用核验，而不是只能看到一段聊天回复。界面当前属于原型实现，真实部署还需补充登录、权限、审计留痕和学校要求的交互规范；本文不将前端展示效果作为法律问答准确率的证据。

报告登记页面仅接受携带非空工作流运行编号的已完成结果：流式模式只信任终态事件中的运行编号，不使用早期节点事件的编号代替；编号缺失时仍可供内部查看，但禁止登记为事项报告并提示重新执行。该门槛仅保存供后续关联的编号，尚未校验编号对应服务端运行记录，更不证明引用语义支持或取代律师审核。

合同审查页面仅在工作流返回 SUCCESS 或 REVIEW_REQUIRED 且报告正文非空时展示报告和风险项；BLOCKED、FAILED 或后续失败事件均清空待展示内容并禁止登记。结构化风险字段按字符串筛选，只有同时具备来源和原文摘录的条目才计入候选引用数量；这些检查只防止畸形响应和无依据的界面计数，不代表完成法源版本或语义支持核验。

法规与判例页面在公共法源检索接口未接入时只显示服务状态，不提供无效的搜索框、订阅按钮或模拟法条。该页面不能作为已完成法规检索功能的演示依据；正式实验需先接入可追溯的版本化来源并验证返回结果。

流程配置草稿页仍可整理文字并调用服务端现有 Agent 进行独立测试，但草稿不能保存、发布或改变现有服务行为。因此不展示无实际作用的知识库勾选框、规则开关与保存按钮；拟接入能力以只读事项列出，避免误导评审认为前端选项已具有权限或安全约束效力。

事项台账将读取失败与真实空列表分开处理：读取失败或列表响应格式异常时撤下旧列表，统计与页签计数显示“—”，重试成功后恢复数据；只有成功返回空数组时才显示零计数。模拟浏览器回归覆盖 390 与 1280 像素宽度下的失败、重试恢复和真实空列表，验证范围限于界面状态，不代表后端权限验收或真实法律问答效果。

模型调用诊断页区分异常列表与正常空记录。非数组响应或非法记录会显示加载错误，不归类为“无调用记录”；调用结果仅依据明确的布尔值显示成功或失败，其他值显示“结果未知”，缺失或非法耗时显示“未记录”，不补作零毫秒。该页面仍为进程内诊断视图，不承担持久化审计档案功能。

律所知识上传仅在服务端回执包含存储状态、文档编号、对象引用、合法 SHA-256 版本摘要及律所知识租户范围时显示“已存储，待入库”；回执不完整或范围不符时保留文件选择并提示核对，不生成成功记录。这里核对的是返回字段的完整性与格式，并未重新读取存储对象验证文件内容，也不能据此推断检索入库完成。上传记录仅存在当前页面；“刷新状态”不清除本页记录，离开页面后不保留。

知识库入库统计只展示非负整数型的文档数、已摄取数、失败数和分片数；接口返回非数字或结构异常时保留未知标记并提示错误，不将解析失败误记为零。模拟浏览器回归验证异常统计与后续刷新为真实零值的状态区别；该测试不证明统计接口的数据真实性或租户隔离。

上传能力接口返回畸形说明、非字符串扩展名或不可用的文件上限时，页面不开放文件选择；只有重新取得有效能力配置后才恢复上传入口。能力接口仅描述当前配置，不是存储连接健康检查，最终仍须依据上传结果判断。

## 第五章 测试与评测

现有自动化测试覆盖原文匹配、错误编号、伪造摘录、版本缺失、无效或未来生效日期、空主张，以及工作流中“通过来源匹配仍需人工复核”“错引不进入报告”“提前流式事件不泄露未核验内容”“诉讼底稿遇错引时隐藏实体分析”“上传授权与上传 SSE 失败不透传异常原文”。前端模拟浏览器回归另外覆盖受阻/失败结果清理、终态覆盖残留节点状态、附件与同步执行互斥、窄屏布局、外链图片阻断和危险链接不跳转。测试材料为虚构示例，只证明程序逻辑。实验应采用确定法域、统一版本的公开法源及人工标注的真实问答集；包括正确引用、同名不同版本、真实引文但错误推论、伪造条号、材料不足、多主张混合等类型。建议两名标注者独立判断、争议由第三人仲裁；固定模型、提示词、温度、语料快照，比较直接大模型、普通 RAG、本系统，记录重复运行次数和成本。

指标：来源可定位率=可定位引用数/生成引用数；摘录准确率=原文匹配引用数/生成引用数；人工主张支持率=人工判定有支持的主张数/被评估主张数；无依据对外结论率=无支持却对外展示的主张数/对外展示主张数；拒答率=拒答问题数/问题总数，并分别统计应拒答和可回答子集。分母为零应记 N/A，不能记为 100%。

### 5.1 可复核的分组方法

实验以“同一问题 ID × 同一运行轮次”为最小配对单元，直接生成、普通 RAG 和本系统三个组必须均有记录；每题重复轮次从 1 开始连续且轮次数相同。固定题库、适用时点、模型参数、知识快照和评分口径；允许组间检索与核验策略不同，但不得用不同的题目或法律版本制造优势。由人工先确定可回答金标准，再对每条实际生成的主张独立判断来源定位、摘录准确、语义支持和是否展示。未完成仲裁的语义标签不能默认计为支持。

### 5.2 指标解释与结果报告

程序对每组逐条统计，并在汇总中输出模型版本、该组提示词版本、语料快照、题目数与每题轮次以便核对配对关系。来源可定位率和摘录准确率以生成主张数为分母；人工支持率仅在已完成支持性判断的主张中计算，并同时报告未判定条数；无支持结论展示率只在实际展示的主张中计算，若有任何已展示但尚未裁决的主张，该比率暂记 N/A。拒答率按运行次数计算，另外分别报告不可回答题的正确拒答率与可回答题的误拒率。分母为零显示 N/A，不能视作算法完美。最终报告还需按题型统计、复核错误实例和运行耗时；当前缺少真实样本及双人标注，故下表保留空白。

### 5.3 效度威胁与审计条件

内部单元测试使用虚构材料，只验证确定性门禁与接口行为，不能推断真实法律问题准确率。真实对照实验还可能受到题型分布、模型随机性、检索语料覆盖、旧法版本混用和标注者分歧的影响。实验前冻结题库、模型与提示词版本、语料快照和问题适用时点；实验后保留逐轮原始输出、双人独立标注与仲裁记录，报告各组相同题目和轮次下的分子、分母、未裁决条数及拒答情况。不能用已展示但未仲裁的主张计算无依据结论率，也不能把程序测试通过率替代法律效果指标。

为防止汇总表与实际展示脱节，每条实验记录应通过 `(questionId, run, group)` 回溯到题库、原始输出及页面或报告，再按主张顺序对照独立标注与仲裁记录；保存证据版本、文件散列和代码提交号。现有统计脚本仅校验输入结构、组间配对和指标计算，不会自动验证截图、原始法源或标注者是否独立。来源版本或输出遗失的轮次不得臆测补齐；记录缺失原因，完成授权与脱敏后才归档可公开材料。具体检查步骤见 `docs/thesis/evaluation-protocol.md`，尚未执行真实样本标注。
