# 受控 Agent 策略改进：离线门禁首版

## 已实现

新增独立 improvement 领域包，不修改法律事项状态机，不接入生产调用链。HarnessVersion 是不可变执行配置，白名单仅含模型标识、清单版本、证据数量和上下文字符预算。模型标识用于比较约束，不代表可选模型已接通。

EvaluationSnapshot 保存冻结输入摘要、总 token 预算与逐案例完成状态、质量分、引用支持、授权、拒答检查及用量；拒绝空集合、重复案例、非有限分值和无效预算，防御性复制案例列表。

OfflineImprovementGate 要求基线/候选版本不同，模型、输入摘要、总预算和案例 ID 集合一致。总用量不得超预算，候选每例必须通过安全及完成检查，每例质量不得下降，平均质量严格提升才进入 PENDING_HUMAN_REVIEW，否则 KEEP_BASELINE。没有自动发布状态。案例顺序不影响平均分比较。

## 明确限制与后续

这是纯领域判定，不是完整 Harness² 复现，也没有自动提出候选、模型调用、隔离执行、持久化、审批 API、回滚部署或前端界面。检查结果是调用方提供的观测值，不是模型可自报的生产凭据；当前未验证观测来源签名或试运行真实性，不能据此自动发布。

输入 SHA-256 仅校验格式和一致性，未来执行器必须从冻结清单计算，清单需覆盖问题、语料、证据版本、评测器版本和留出集定义；不能由候选自由指定。质量分需由独立评测器生成，引用/授权/拒答由确定性检查和人工复核补足。现有预算字段只是事后判定，不能代替实际执行器的超时、工具副作用隔离和硬 token 限制。版本 ID 尚无仓储唯一性约束，后续应持久化不可变配置及内容哈希，并将租户与适用场景纳入存储授权。

优先下一步：接入只读离线运行器和独立留出评测，不开放真实客户请求自动优化；任何通过候选仍需由有权限的人员审核，法律交付仍经过既有事项复核与律师签署。
