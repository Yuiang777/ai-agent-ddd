# 2026-10-21 多模态任务所有权与异常边界修复

## 范围

针对综合检查报告24中的多模态隔离和异常外泄路径，修改 MultimodalService、MultimodalController，补充6项 MultimodalOwnershipTest 及现有真实 HTTP 集成断言。不变更前端响应字段，不开放新功能。

## 修复

- 任务内部保存独立 OwnedTask 包装，绑定创建时的 tenantId + actorId，不向 API 增加身份字段。任务提交开始就检查身份；安全模式缺主体拒绝，CLIENT、SYSTEM、空角色拒绝；仅 LAWYER/PARALEGAL 可用，不提供隐式全局运维旁路。仅关闭企业安全且缺主体时保留固定离线身份兼容行为。
- 列表过滤当前所有者；详情未知或非所有者统一视为不存在。任务写入与顺序/容量维护置于同一锁内，避免修改映射时顺序索引尚未更新。
- 资产必须同时满足当前身份、任务关联 URL、严格文件名白名单和普通非符号链接文件检查；单纯知道磁盘文件名不再足以下载。没有所有权记录的旧文件不自动认领。
- 保留临时文件清理语义：执行结束即删除，不能把返回的临时资产 URL 当作持久证据下载链接。
- 能力、列表、详情接口的身份拒绝使用 MULTIMODAL_ACCESS_DENIED，资产身份拒绝为 HTTP 403。一般边界异常为 MULTIMODAL_REQUEST_FAILED；已创建任务的执行异常返回 failed 状态及 MULTIMODAL_EXECUTION_FAILED，沿用前端既有 success envelope + task.status 契约。
- 任务失败不保存上游异常原文，服务任务失败日志只记录任务ID和异常类型；临时清理日志也不写异常原文。此次不宣称第三方 SDK、MCP 或整个应用所有日志都已全面脱敏。
